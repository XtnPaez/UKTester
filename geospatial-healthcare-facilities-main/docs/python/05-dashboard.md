# Dashboard

This guide explains how to render the Quarto dashboard (`hcf-dashboard-python.qmd`) and run it interactively via Shiny.

The dashboard visualises healthcare accessibility metrics interactively. It is built using a Quarto `.qmd` file backed by Shiny for Python, and is served locally via `shiny run`.

## Prerequisites

### Environment

The dashboard requires the same Python environment as the rest of the project. If you have not already set it up, follow [01 — Installation](01-installation.md). Ensure the `healthcare_accessibility` package is installed in editable mode from the project root:

```bash
pip install -e .
```

### Quarto

Quarto must be installed on your system. Download the latest release from [quarto.org](https://quarto.org/docs/get-started/).

Verify your installation:

```bash
quarto --version
```

### Required data outputs

The dashboard reads pre-computed travel time parquet files and processed geospatial data. Before rendering, you must have completed the full analysis pipeline so that the following exist for your configured country (e.g. `Nepal`):

```text
outputs/<country>/bicycle_travel_times_to_All healthcare facilities.parquet
outputs/<country>/walk_travel_times_to_All healthcare facilities.parquet     # optional
outputs/<country>/car_travel_times_to_All healthcare facilities.parquet      # optional
data/<country>/processed_data/healthcare_facility_data.gpkg
data/<country>/processed_data/master_population_grid_data.gpkg
data/<country>/raw_data/admin_boundary_geom/<ISO3>_ADM2_geoboundaries.geojson
```

Refer to [03 — Data preparation](03-data-preparation.md) and [04 — Travel time analysis](04-travel-time-analysis.md) for instructions on generating these files.

### Configuration

Open `configs/config.yaml` and confirm the `country` field matches the context you want to visualise:

```yaml
country: Nepal
```

All file paths in the dashboard are derived from this value. No changes to the `.qmd` file itself are required.

## Step 1 — Render the dashboard

The dashboard uses Quarto's `server: shiny` mode, which means it cannot be rendered to a fully static HTML file that works offline. Instead, you render it into a bundle of assets that Shiny serves at runtime.

From the repository root:

```bash
quarto render src/healthcare_accessibility/hcf-dashboard-python.qmd
```

This produces:

- `src/healthcare_accessibility/hcf-dashboard-python.html` — the entry point
- `src/healthcare_accessibility/hcf-dashboard-python_files/` — supporting JS/CSS assets

> **Note:** The rendered HTML is not interactive on its own. It must be served through Shiny (step 2).

## Step 2 — Launch with Shiny

From the repository root:

```bash
shiny run src/healthcare_accessibility/app.py
```

Open the URL printed in the terminal (typically `http://localhost:<port>`) in your browser.

### What `shiny run` does

- Starts a local Shiny Python server using `app.py`, which was generated by the Quarto render step.
- Loads the setup chunk (data reading, config parsing) once on startup.
- Serves reactive UI elements (filters, map updates) in response to user input.

## Interacting with the dashboard

Once open in a browser, the dashboard provides controls to filter and explore healthcare accessibility metrics:

| Control | Description |
| --- | --- |
| Admin area selector | Filter to a specific ADM2 district or view nationally |
| Facility type filter | Select one or more healthcare facility categories to restrict the map and summary statistics |
| Distance threshold | Set the km radius used to classify population as "within reach" |
| Travel mode selector | Switch between bicycle, walking, and car travel times (only available if the corresponding parquet file exists in `outputs/<country>/`) |
| Demographic selector | View accessibility metrics for the total population or specific demographic groups (male, female, age bands) |
| Show outside toggle | Include or exclude population beyond the distance threshold |
| Facility breakdown button | View a count breakdown of facilities by type |
| Map | Interactive Folium map that updates in response to filters, showing facility locations and population grid cells coloured by travel distance |

## Re-rendering after changes

If you modify `hcf-dashboard-python.qmd` or any module in `src/healthcare_accessibility/`, re-run the render step then restart `shiny run`.

If the dashboard shows unexpected behaviour after re-rendering, clear the cached asset directory and re-render:

```bash
Remove-Item -Recurse -Force src/healthcare_accessibility/hcf-dashboard-python_files
quarto render src/healthcare_accessibility/hcf-dashboard-python.qmd
shiny run src/healthcare_accessibility/app.py
```

These files will be fully regenerated — deleting them causes no lasting harm.

## Troubleshooting

Common dashboard-specific issues:

| Problem | Likely cause | Fix |
| --- | --- | --- |
| `FileNotFoundError` on startup | Missing parquet or `.gpkg` file | Run the full pipeline first; check `configs/config.yaml` `country` value |
| `ModuleNotFoundError: healthcare_accessibility` | Package not installed | Run `pip install -e .` from the project root |
| `quarto: command not found` | Quarto not on PATH | Install Quarto and restart your shell |
| Dashboard loads but map is blank | CRS mismatch or empty data | Verify processed data files contain rows for the configured country |
| Shiny server port conflict | Another process on the default port | Pass `--port <number>` to `shiny run`, e.g. `shiny run src/healthcare_accessibility/app.py --port 8081` |
| Unexpected behaviour after re-render | Stale cached asset files | Delete `hcf-dashboard-python_files/` and re-run render and `shiny run` |

See [06 — Troubleshooting](06-troubleshooting.md) for errors relating to earlier pipeline stages.
